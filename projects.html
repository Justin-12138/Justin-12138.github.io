01 Internal 2024 — 2025

Document intelligence / RAG

Article-tree retrieval for document QA

Long annual reports were being flattened into fixed chunks and losing the structure that made them answerable. I rebuilt retrieval around the document's title hierarchy.

Context
LLM development, algorithm team. The test set was a group of AIA annual reports from 2022–2025, roughly 76–99 pages each.
Problem
Fixed-chunk RAG returned text that was topical but not sufficient: the right year, table header or footnote often sat in a different chunk. Similarity to the query was a poor proxy for evidence.
Approach
Two companion prototypes: ragdetail compared dense, BM25 + dense hybrid, and hybrid + rerank on page-level retrieval; optpgi converted PDFs to Markdown with a VLM, built a title tree, and retrieved over document and page summaries before loading only the needed body text.
What was hard
Cascade failures. A document-level prompt that preferred the latest report could discard the older document holding half the evidence before page selection ever ran. Page lists for a single report also consumed roughly 22–29k tokens, so "just send the tree" did not scale.
Outcome
Article-tree retrieval was more accurate than fixed-chunk retrieval on the internal evaluation, and the architecture became the basis of the public write-up below. No numbers are published, so none are claimed here.

02 Internal 2024 — now

LLM infrastructure / serving

Inference benchmarks and KV-cache experiments

Day-to-day work on the layer between the model and the request: which serving framework, which parallelism strategy, and where the memory actually goes.

Context
Algorithm engineer in the algorithm team at Isoftstone, working on AI infrastructure: serving evaluation, training-platform tooling and applied LLM systems.
Problem
Throughput and latency numbers are easy to produce and hard to compare. KV cache, batching, quantization and distributed strategies interact, and a benchmark can silently measure the wrong thing.
Approach
Benchmarked vLLM, SGLang and LMDeploy; worked with KV-cache reuse and memory accounting using LMCache and Dynamo; studied DP/TP/PP/EP trade-offs. Separately, extended LlamaFactory with a cross-container data-parallel API to reduce configuration overhead.
What was hard
Keeping the comparison honest. Workload shape, prefix reuse, concurrency and output length change the conclusion. The useful output was less a single throughput figure and more a map of which conditions favour which setup.
Outcome
Internal serving work, plus three public learning notes on KV cache, GPU architecture and LLM output consistency. No internal metrics or customer details are published.

03 Public 2023 — 2024

Research / Causal inference

Alzheimer's biomarker discovery

A feature-selection project on gene-expression data, and my first real encounter with research-grade ambiguity.

Context
Project lead at the School of Artificial Intelligence, GUET. The work became a first-author paper at ICAI 2024.
Problem
Biomarker discovery from high-dimensional expression data: many candidate features, limited samples, and a strong temptation to trust whichever method produces the cleanest ranking.
Approach
Collected data from GEO, then compared MRMR, CFS and causal-inference-based feature selection. The comparison, rather than a single method, was the point.
What was hard
Defending the choices. Data processing and feature-selection assumptions change the result, and writing the paper forced every shortcut into the open.
Outcome
“Causal Inference-Based Feature Selection Method for Identifying Alzheimer's Disease Biomarker”, ICAI 2024, Springer. Presented at the conference; code is public.

04 Internal 2024 — 2025

Agents / Applied AI

Discussion-based multi-agent systems

Several agents arguing their way to a result, plus a generative step for product imagery.

Context
Applied AI work in the algorithm team, exploring how agent frameworks behave on tasks that need more than one pass.
Problem
A single model call tends to collapse a multi-step task into one answer. Splitting the work into roles can help, but adds orchestration, state and new failure modes.
Approach
Built discussion-based multi-agent flows with LangGraph, AutoGen and Google ADK, paired with Nano-Banana-pro for product imagery.
What was hard
The model call is the easy part. Hand-offs, shared state and deciding when the conversation is actually finished are where these systems become engineering.
Outcome
Internal prototypes. No public repository or client details.
